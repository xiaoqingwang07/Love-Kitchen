# 图床迁移 · 操作说明（给非技术同学）

目的：把菜谱图从「盗链下厨房」改成「存在你自己的图床」，避免哪天被断链导致图片集体变空白。

这件事**在你自己电脑上跑一次**就好（我那边的环境连不上图床，跑不了）。

## 准备（一次性）

1. 开通一个对象存储，二选一即可：
   - 腾讯云 COS（推荐，文档最友好）
   - 阿里云 OSS
2. 新建一个 bucket（桶），权限设为「公有读」。
3. 拿到 4 样东西：`SecretId`、`SecretKey`、桶名、地域（如 `ap-guangzhou`）。
4. 最好给桶绑一个自定义域名 / CDN，得到一个图片访问根地址，例如 `https://img.yourdomain.com`。

## 执行（在项目根目录）

```bash
# 0. 先提交一次，留好后路
git add -A && git commit -m "chore: 迁移前快照"

# 1. 装唯一依赖
npm i -D @aws-sdk/client-s3

# 2. 打开 scripts/migrate-images.mjs，把最上面 CONFIG 那一块填好
#    （endpoint / region / bucket / SecretId / SecretKey / CDN_BASE）

# 3. 先演练（默认 DRY_RUN=true，只报告不改动）
node scripts/migrate-images.mjs

# 4. 看报告没问题后，把 CONFIG.DRY_RUN 改成 false，再跑一次（真正下载+上传+改代码）
node scripts/migrate-images.mjs

# 5. 本地预览，确认图片正常显示，然后提交
git add -A && git commit -m "feat: 菜谱图迁移到自有图床"
```

## 出问题怎么办

- 图片没显示 / 想反悔：`git checkout src/data/` 一键还原（脚本也会生成 `*.bak` 备份）。
- 上传报权限错误：检查桶是否「公有读」、SecretKey 是否正确、地域是否填对。
- 跑到一半失败：脚本会跳过「已上传」的图，直接重跑即可，不会重复传。

有任何一步卡住，把报错贴给我，我帮你看。
