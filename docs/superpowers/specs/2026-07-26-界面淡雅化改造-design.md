# 爱心厨房 · 界面淡雅化改造方案

日期：2026-07-26
状态：待实施
范围：视觉与排版改造，**不改功能、不改数据、不改页面路由**

---

## 一、为什么要做

用户（产品所有者）的原话：「我不喜欢现在的界面，做的太粗糙了，一点都不苹果」「我喜欢那种极简风格，点进去功能又很丰富」「色调能不能再淡一点，要看起来轻量一点，有呼吸感」。

排查后确认，「粗糙」不只是审美问题，存在若干**实打实的排版缺陷**。本方案同时修缺陷和换视觉。

---

## 二、已核实的缺陷

以下每条都经过实际验证，不是推测。验证方式记录在括号内。

### 1. 标题与副标题黏连（严重）

首页 `src/pages/index/index.tsx:227-228` 中两个 `<Text>` 相邻放置：

```tsx
<Text style={S.titleStyle}>今晚吃什么？</Text>
<Text style={S.titleHintStyle}>拍小票建冰箱，或直接搜食材</Text>
```

`titleHintStyle` 设了 `marginTop: 10`，但 `Text` 默认是行内元素，上边距不生效，两行文字挤在同一行，副标题还会被从中间断开（实测渲染为「今晚吃什么？拍小票建冰 / 箱，或直接搜食材」）。

- **验证方式**：H5 构建后在浏览器实测截图确认。
- **范围**：全项目 59 个 `.tsx` 文件、294 处 `<Text>`，其中相邻 `Text` 兄弟节点广泛存在（`pick/index.tsx` 单文件 25 处）。首页、今晚页、冰箱页均已在截图中观察到同类现象。
- **⚠ 待确认**：上述验证在 H5 构建上完成。小程序端 `text` 组件同样默认 `display: inline`，预期表现一致，但**实施时必须在微信开发者工具模拟器中复核**，不可仅凭 H5 结论收工。

### 2. 全局行距过松

`src/app.scss:9` 对 `page` 设置 `line-height: 1.47`，该值继承到所有文字，包括大标题和小字说明。实测冰箱页一句 24 字的说明撑成两行且行间空隙明显过大。

- **验证方式**：读源码 + H5 截图。

### 3. 功能图标 PNG 是坏文件

`src/assets/icons/` 下 12 个 PNG（camera/meal/search/mic/cart/fridge/share/add/cook/list/home/heart）内容均为「一个纯色圆角方块 + 中间一个小到无法辨认的字符」。

`src/components/AppIcon.tsx:70-85` 的逻辑是「PNG 存在就用 PNG，否则回退汉字 glyph」。由于坏 PNG 文件确实存在，程序判定有图标，于是**优先渲染方块，把本来可用的汉字兜底方案挡住了**。

- **验证方式**：直接打开 `camera.png`、`fridge.png` 目视确认；同时在浏览器中确认 `img` 元素 `naturalWidth=48` 加载成功（即"图标没加载"的说法不成立，是文件本身坏）。
- **附带问题**：`AppIcon` 的 `color` 属性在 PNG 分支被完全忽略，导致图标无法随按钮底色变色。

### 4. 底部 tabBar 图标质量差

`src/app.config.ts:22-53` 引用 `src/assets/tabbar/` 下 8 个 PNG，文件大小仅 283–388 字节。

- `home.png`：实心房子，笨重
- `pick.png`（今晚）：**形似 ♀ 符号，与「吃饭」无任何视觉关联**
- `pantry.png`（冰箱）：双开门冰箱轮廓，尚可
- `profile.png`（我的）：实心人形，尚可

分辨率过低，高清屏发虚；实心色块与目标的细线条风格不符。

- **验证方式**：逐个打开 PNG 目视确认 + `ls -la` 确认文件体积。

### 5. 卡片高度不齐 / 底部悬浮条压住内容

冰箱页「共 18 项 / 临期 5 / 过期 2」三张卡片高度不一致（中间那张多一个按钮就变高）；底部悬浮操作条遮挡下方内容，并露出被截断的黑色圆角元素。

- **验证方式**：H5 截图观察。
- **⚠ 待确认**：同样需在模拟器复核。

### 6. 圆角与硬编码色值不统一

- `designTokens.ts` 定义了 4 档圆角（12/16/20/28），页面混用，缺乏统一节奏。
- 存在绕过设计变量的硬编码色值：`#F5412C`×6、`#1AA251`×3、`#FF6B3D`×2、`#F6F8F5`×2 等，换肤时会成为漏网之鱼。

## 三、设计方向（已与用户逐版确认）

经过 5 轮可视化比对（暖色毛玻璃 → 极简 → 加回层次 → 修三处问题 → 调淡），最终确认方向为**淡雅暖色 + 强层次**。

关键认知：**极简不等于扁平**。中间过程曾把所有元素拉到同一视觉重量，用户反馈「看着没层次」。最终方案通过**字号跨度**和**真实照片**建立层次，而非增加框线和色块。

### 3.1 色板

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面底 | `#FDFCFB` | 几乎纯白，一丝暖意 |
| 卡片 | `#FFFFFF` | |
| 提醒底 | `#FEF8F3` | 淡到几乎白 |
| 主色 | `#E89562` | 杏橙。原 `#1AA251` 鲜绿弃用 |
| 正文 | `#3A342E` | 暖灰褐，替代近纯黑 |
| 次要字 | `#BEB6AE` | |
| 三级字 | `#C6BFB8` | |
| 分隔线 | `#F5F1ED` | |

### 3.2 字号阶梯

拉开跨度以建立层次（原字号挤在 11–17 之间，是「没层次」的根因）：

| 层级 | 字号 | 字重 | 用途 |
|---|---|---|---|
| 大标题 | 31 | 600 | 页面主标题 |
| 主角 | 20 | 600 | 菜名等主体对象 |
| 正文 | 15 | 600（可点条目）/ 400（普通段落） | |
| 说明 | 12.5 | 400 | 时长、步数等 |
| 分组标签 | 10.5 | 500 | 字间距 1.6 |

### 3.3 其他规则

- **圆角收敛为 3 档**（替代现有 12/16/20/28 四档混用）：
  - 小元素（标签、搜索框、次级按钮）= 14
  - 卡片、提醒条 = 18
  - 胶囊按钮 = 999（全圆）
- **行距**：标题 1.15、正文 1.5，取消全局 1.47 继承
- **阴影**：基本删除，靠留白分层
- **间距**：分组间隔 30，卡片内边距 14（原 22 / 11）
- **一屏一个实心按钮**：主操作实心橙，次操作白底橙字

## 四、首页重构（方案 A · 提醒置顶）

用户在两个方案中选定 A。

### 结构（从上到下）

```
7月26日 · 周日          ← 日期锚点，弱化
今晚吃什么？             ← 31px 大标题，独占一行

┌─────────────────────────────┐
│  7   样食材快过期    [去处理] │  ← 提醒条置顶，淡橙底
│      菠菜、豆腐、鸡胸肉 等     │     处理完自动消失
└─────────────────────────────┘

[🔍 番茄、鸡蛋、鸡胸肉…  🎙 📷]

今晚推荐
┌─────────────────────────────┐
│ [真实菜图]  干锅土豆虾        │  ← 76×76 横向小卡
│  76×76     20 分钟 · 3 步    │
│            [用掉 2 样临期]    │
└─────────────────────────────┘
[        就做这个        ]      ← 全页唯一实心按钮

冰箱 18 样    待采购 0          ← 统计降级为一行小字
```

### 具体变更

1. **临期提醒置顶**。理由：临期是有时效的坏消息，晚看一天就浪费。冰箱无临期时该条**整体不渲染**，首页更干净。
2. **删除右上角「收藏」入口**。经查 `src/pages/index/index.tsx:230-239`，该入口调用 `setProfileOpenFavorites()` 后 `switchTab` 到 profile 页，**与底部「我的」tab 是同一目的地**，仅省一次点击，属功能重复且挤占标题空间。
3. **删除副标题**「拍小票建冰箱，或直接搜食材」，搜索框自身已表达该信息。
4. **推荐卡改横向紧凑布局**，配**真实菜谱封面图**。
5. **「厨房状态」三个大数字降级**为一行小字，让位给主任务。

### ⚠ 配图可信度红线

推荐卡必须使用**与菜名相符的真实图片**。方案讨论中曾用 🍤 符号占位，被用户指出「干锅土豆虾配一只虾，图文不符」——该判断正确，此为本项目红线。

实施要求：
- 图片取自 catalog（如 `干锅土豆虾` id=1704，封面 URL 已验证 HTTP 200 且目视确认图中含虾、土豆条、芹菜、香菜，与菜名相符）。
- **任何新增/更换配图必须目视验证后才可采用**。历史教训：catalog 候选图中出现过「油焖大虾」配超市门头照、「卤肉饭」配印着"罗宋汤"的图。
- 无可靠配图时，**宁可回退 emoji 也不展示错图**。

## 五、tabBar 图标重做

重新生成 4 组共 8 个 PNG（常态 + 选中态）：

- 风格：细线条描边，线宽 1.5，非实心
- 尺寸：81×81（3x），解决高清屏发虚
- 形状：首页=房子轮廓；**今晚=碗（替换现有 ♀ 形状）**；冰箱=双门冰箱（沿用现有造型）；我的=人形轮廓
- 配色：常态 `#C6BFB8`，选中 `#E89562`
- 同步更新 `app.config.ts` 的 `color` / `selectedColor` / `backgroundColor`

## 六、其余 4 屏

今晚（pick）、冰箱（pantry）、详情（detail）、我的（profile）**不改结构**，仅套用同一套设计变量与排版规则：

- 大标题与副标题拆行
- 行距按新规则
- 圆角统一
- 硬编码色值收归设计变量
- 卡片等高、底部悬浮条留出安全距离

---

## 七、实施顺序

改动集中在设计变量层，57 个文件引用 `designTokens`，**改一处全局生效**，因此按「先全局、后局部」推进：

1. `src/theme/designTokens.ts` 换色板 + 字号阶梯 + 圆角统一
2. `src/app.scss` 行距分层
3. 全局 `Text` 换行修复（新增共用样式，避免逐处硬改）
4. 删除 `src/assets/icons/` 坏 PNG，`AppIcon` 走汉字兜底
5. 重做 tabBar 图标 + `app.config.ts`
6. 首页按方案 A 重构
7. 其余 4 屏套用规则
8. 收敛硬编码色值

## 八、验证方式

每一步完成后：

- `npm run verify:all`（typecheck + 回归 + 发布检查 + 构建 + 包体积）必须全绿
- H5 构建后在浏览器逐屏截图核对
- **微信开发者工具模拟器复核**（关键：第 1、5 条缺陷的 H5 结论需在小程序端确认）
- 配图逐张目视验证

---

## 九、明确不做

- 不改任何功能逻辑、数据结构、页面路由
- 不做图床自有化（另立项）
- 不动 catalog 数据
- **不自动推送 GitHub**——代码改完由用户确认后再决定是否推送

## 十、遗留事项（与本方案无关但已发现）

微信端小程序当前显示「小程序尚未发布」，用户原以为已上线。可能原因：开发者工具预览二维码 25 分钟过期，或体验版未上传/微信号不在体验成员名单。需用户在开发者工具重新生成预览码，或在公众平台处理。此事不阻塞本次改造。
